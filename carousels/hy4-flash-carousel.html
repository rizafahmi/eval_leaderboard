STUDI KASUS #1 CTRL-C

Menangani Ctrl-C dengan mulus. Termasuk saat aplikasi baru mulai jalan.

01

Kendala awal

Secara default, Ctrl-C langsung memutus program sehinga ringkasan hasil gagal tercetak.

02

Solusi model

Terminal diatur agar Ctrl-C terbaca sebagai input biasa, bukan sinyal sistem.

03

Alur berhenti

Request baru dihentikan, proses aktif diselesaikan, ringkasan tercetak, terminal kembali normal.

Hasil Uji: 5 / 5 Lolos

Termasuk di 50 ms awal saat aplikasi mulai — semua tetap mencetak ringkasan & keluar dengan kode 130.

STUDI KASUS #2 DEBUGGING

Menemukan penyebab bug timeout yang cukup rumit. Diperbaiki dengan satu baris kode.

01

Gejala

Saat memakai ulang koneksi HTTP, sebagian request terus gagal karena timeout.

02

Analisa mandiri

Model melacak sendiri penyebabnya: state koneksi terbaru lupa disimpan kembali.

03

Perbaikan

Cukup ubah 1 baris kode, seluruh 50/50 request langsung berjalan normal.

Detail Teknis di Halaman Web

Potongan kode, log jarak antar request, dan diff perbaikannya tersimpan lengkap di catatan sesi.
